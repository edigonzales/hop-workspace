## Type- und Consumer-PRs

- [Raster Type](https://github.com/edigonzales/hop-raster-type-plugin/pull/3) → [Vector/Raster](https://github.com/edigonzales/hop-vector-raster-plugin/pull/10). Die lokale Paarprüfung nutzte die beiden R2-Artefakte. Die Vector/Raster-CI bezieht den publizierten Raster-Snapshot. Der Companion-Job von Raster Type verwendet standardmässig Vector/Raster `main` und kann über `companion_ref` den R2-Branch wählen.
- [Point Cloud Type](https://github.com/edigonzales/hop-pointcloud-type-plugin/pull/2) → [PDAL](https://github.com/edigonzales/hop-pdal-plugin/pull/1). PDAL wurde lokal gegen die R2-Type-Artefakte geprüft. Die reguläre PDAL-CI baut den Type vom Default-Branch. Die beiden installierten Kandidaten gehören zusammen, weil ältere PDAL-Builds das entfernte `PointCloudBackend` implementieren.
- [Geometry Type](https://github.com/edigonzales/hop-geometry-type-plugin/pull/13) → [Geometry Inspector](https://github.com/edigonzales/hop-geometry-inspector-plugin/pull/12). Der Inspector wechselt direkt auf `ValueMetaGeometry` und wurde mit dem 06a-JAR und -ZIP geprüft. Seine CI baut Geometry Type von `main`. Ältere Inspector-Builds benötigen noch das entfernte `GeometryInterface`.
- [Geometry Calculator](https://github.com/edigonzales/hop-geometry-calculator-plugin/pull/4) und der [GraalPy-Geometry-Handoff](https://github.com/edigonzales/hop-python-plugin/pull/3) wurden zusätzlich gegen das 06a-Artefakt geprüft. Die Calculator-CI baut Geometry Type von `main`, der GraalPy-Handoff lädt den publizierten Snapshot. [Geoprocessing](https://github.com/edigonzales/hop-geoprocessing-plugin/pull/11), Raster Type, Vector/Raster und [INTERLIS](https://github.com/edigonzales/hop-interlis-plugin/pull/8) nutzen Geometry Type ebenfalls. Ihre frühere Paketabnahme lief mit dem Stand vor 06a.

Die Prüfspalte dokumentiert die lokale R2-Abnahme. GitHub Actions kann je nach Workflow die Default-Branches oder publizierten Snapshots der Type-Repositories verwenden.

Die Klasse fehlt im R2-Raster-ZIP und blockierte alle sechs installierten E2E-Jobs. Der separate Paarlauf verwendet Raster Type `a1b4c9c` und Vector/Raster `5f64a72` über `companion_ref`. [E2E-Job aus Versuch 2](https://github.com/edigonzales/hop-raster-type-plugin/actions/runs/45331856313/job/138667347178), [R2-Paarlauf](https://github.com/edigonzales/hop-raster-type-plugin/actions/runs/45457050612)

Derselbe Fehler trat unter Linux, macOS und Windows jeweils mit Java 21 und 25 auf. Die lokale Paarprüfung mit dem 02a-ZIP war grün. Der dabei erzeugte Thread-Dump zeigt Maven Surefire beim Warten auf die Test-JVM. Die genaue Ursache innerhalb des SWT-Tests ist offen, die Windows-Paketprüfung kam nicht zum Zug.
